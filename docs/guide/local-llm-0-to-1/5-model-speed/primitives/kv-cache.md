# KV Cache (키-밸류 캐시)

## 이게 뭐예요?
**LLM이 이미 읽은 토큰의 어텐션 계산 결과를 메모리에 저장해 두는 기술**이에요. 저장하지 않으면 매 토큰마다 입력 전체를 다시 계산해야 해서 속도가 극도로 느려집니다.

> 💡 비유: 에세이를 쓸 때 **"앞서 쓴 내용을 매 문장마다 다시 읽지 않고 메모장에 적어두는 것"** 과 같아요. 메모장에 적어두면(KV Cache) 다음 문장은 바로 메모장을 참고해서 쓰면 되지만, 안 적어두면 매번 처음부터 끝까지 다시 읽어야 해요.

## 왜 중요해요?

KV Cache는 **메모리 사용량과 모델 품질**을 동시에 좌우합니다. 컨텍스트가 길어질수록 그 영향이 커집니다.

### 핵심 — KV Cache 양자화

모델 가중치를 양자화(Q4, Q8)하는 것처럼 **KV Cache 자체도 양자화할 수** 있어요. 여기서 트레이드오프가 생깁니다.

| KV Cache 설정 | 메모리 사용 | 모델 품질 |
|---|---|---|
| `f16` (압축 없음, 기본값) | 최대 | 원본 유지 |
| `q8_0` (8-bit 압축) | 약 50% 절감 | 약간 ↓ |
| `q4_0` (4-bit 압축) | 약 75% 절감 | 뚜렷하게 ↓ |

> ⚠️ **컨텍스트가 길어질수록 압축의 피해가 커져요.** 짧은 대화에서는 q8/q4 차이가 거의 안 나지만, 32K 토큰 이상으로 가면 압축한 KV Cache에서 모델이 "세부 정보를 잊어버리거나 환각"을 일으키기 시작합니다.

## llama.cpp에서 설정하기

### 기본값 (압축 없음 — 권장)

별도 플래그 없이 실행하면 **f16**이 기본값입니다. 메모리가 충분하다면 이게 최선이에요:

```sh
llama-server -m model.gguf -c 131072   # KV Cache는 f16 (압축 없음)
```

### 압축하기 (메모리 부족할 때만)

`--kv-cache-type` 플래그로 Key와 Value를 각각 다른 정밀도로 설정할 수 있어요:

```sh
# Key와 Value 모두 q8
--kv-cache-type k8:v8

# Key는 q4, Value는 q8 (Value가 품질에 더 영향 줌)
--kv-cache-type k4:v8
```

### 어떻게 선택할까?

| 상황 | 추천 설정 |
|---|---|
| M4 Max 128GB + 27B Q8 | **f16** (압축 없음) — 메모리 충분 |
| 컨텍스트 32K 이상 + agentic 작업 | **f16** — 품질 유지 필수 |
| VRAM 부족으로 자주 drop되는 경우 | **k8:v8** — 최소한의 압축 |
| 단말 GPU + 긴 컨텍스트 | **k4:v8** — 마지막 수단 |

## 메모리 사용량 계산

KV Cache가 먹는 메모리는 컨텍스트 길이에 비례해요:

```
KV Cache (GB) ≈ 컨텍스트 길이 × 레이어 수 × 헤드 수 × 헤드 크기 × 2(K+V) × 정밀도
```

간단한 추정 (27B 기준):

| 컨텍스트 | f16 (기본) | q8_0 | q4_0 |
|---|---|---|---|
| 8K | ~1.5GB | ~0.8GB | ~0.4GB |
| 32K | ~6GB | ~3GB | ~1.5GB |
| 128K | ~24GB | ~12GB | ~6GB |

128K 컨텍스트에서 f16과 q4_0이 **18GB 차이**예요. 메모리가 빠듯한 환경에서는 큰 숫자입니다.

## 정리
- KV Cache = 이미 계산한 어텐션 결과를 저장해 속도를 높이는 기술
- 압축 안 하면(f16) 품질 유지, 압축하면(q8/q4) 메모리 절감
- 컨텍스트 길어질수록 압축의 피해가 커짐
- M4 Max 128GB라면 **압축 없이 f16** 돌리는 게 최선
