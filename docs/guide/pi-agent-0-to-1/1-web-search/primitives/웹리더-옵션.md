# 웹 리더: 옵션

## 이게 뭐예요?

검색으로 받은 `url`에 들어가서 본문을 깨끗한 텍스트로 뽑아주는 도구들이에요. [[웹검색-원리]]의 `2단계(읽기)`를 맡아요. 1단계 검색엔진([[웹검색엔진-무료옵션]])이 "목록"을 주면, 웹 리더는 그 링크의 "본문"을 가져옵니다.

웹페이지엔 광고·메뉴·댓글이 잔뜩 섞여 있어요. 좋은 웹 리더는 거기서 **진짜 본문만** 골라 마크다운으로 줘서, 모델이 바로 사용할 수 있게합니다. 잘 만든 건 JS로 그리는 페이지도 렌더링해서 읽어내고요.

좋은 소식: 아래 셋은 **전부 self-host하면 공짜**(오픈소스)예요. 그래서 비용은 판단 기준이 아니고, **품질·무게·우리 스택과의 궁합**으로 고르면 됩니다.

## 한눈에 보기
| 도구 | 한 줄 설명 | JS 렌더링 | 형태 | 링크 |
|---|---|---|---|---|
| Jina Reader | URL을 마크다운으로. 렌더링+추출 한 번에 | O (dual-engine) | Docker 서비스 | https://github.com/jina-ai/reader |

### Jina Reader: 우리 패턴에 딱 맞음
**강점**
- **Apache-2.0** 완전 오픈소스. Docker 이미지가 이미 빌드돼 있어서 self-host가 `docker run` 한 줄이에요. [[searxng]]랑 똑같은 패턴.
- **JS 렌더링 내장**(Puppeteer + 헤드리스 Chrome). 게다가 **dual-engine**이라 가벼운 방식으로 먼저 시도하고, 안 되면 브라우저로 폴백해요. 품질과 속도를 같이 잡습니다.
- 결과를 **마크다운**으로 바로 줘요 (모델 친화). html, text, 스크린샷, json도 됨.
- self-host는 rate limit이 없어요.

**약점**
- 브라우저를 품고 있어서 **이미지가 무거워요** (디스크·메모리). 셋업 난이도가 아니라 덩치 얘기예요.
- 호스티드(r.jina.ai)는 rate limit이 있고, 높은 한도는 API 키가 필요해요. (우리는 self-host라 무관.)

🔗 https://github.com/jina-ai/reader · 호스티드 https://r.jina.ai

### Firecrawl: 기능 풍부한 올인원
**강점**
- 렌더링 + 본문 추출 + 마크다운을 한 서비스로 다 해줘요. **여러 페이지 크롤링**까지 됩니다.
- self-host 오픈소스라 **공짜**로 돌릴 수 있어요.

**약점**
- self-host 셋업이 **무거워요** (Playwright, Redis 등이 딸려옴). SearXNG보다 큽니다.
- **클라우드에만 있는 추가 기능**이 있어서, self-host 버전은 일부가 빠져요.
- 라이선스가 **AGPL-3.0**이에요. 개인이 로컬에서 쓰는 건 전혀 문제없지만, 검색쪽 도구들보다 빡빡한 편.
- 클라우드 API는 유료예요 (무료 1,000페이지/월, 이후 월 $16~).

🔗 https://github.com/firecrawl/firecrawl · https://www.firecrawl.dev

### Trafilatura: 추출 정밀도 챔피언
**강점**
- **본문 추출 품질이 벤치마크 최상위**예요. 여러 논문(Lejeune & Barbaresi 2020, Bevendorff et al. 2023 등)에서 1등으로 꼽혔어요.
- 제목·날짜·저자 같은 **메타데이터**도 같이 뽑아요. 출력은 텍스트, 마크다운, XML 등 다양.
- 브라우저가 없어서 **가볍고 빨라요**. Apache-2.0 오픈소스.

**약점**
- **Python**이에요. 우리 TS 확장 안에 바로 못 넣어요. 쓰려면 별도 서비스로 띄워야 합니다.
- **JS 렌더링을 안 해요.** 주어진 HTML에서 본문만 뽑는 도구라, JS로 본문을 그리는 페이지(SPA)는 못 읽어요. 정적 페이지 전용이에요.

🔗 https://github.com/adbar/trafilatura · 문서 https://trafilatura.readthedocs.io

## 이 시리즈에선: Jina Reader
끝까지 로컬로 가는 우리 취지엔 **Jina Reader self-host**가 정답이에요. **Docker 한 줄로 뜨고**([[searxng]]와 같은 패턴), **JS 렌더링에 dual-engine**까지 갖춰 품질과 효율을 같이 잡고, **마크다운**으로 바로 줍니다. 검색(SearXNG)과 읽기(Jina Reader)가 둘 다 로컬 Docker 서비스로 대칭이 돼서 구조도 깔끔해요.

- **Trafilatura**는 추출 정밀도는 최강이지만 Python이고 JS를 못 읽어서, 우리 스택에선 손이 더 가요. 정적 페이지만 다루거나 추출 정밀도가 절대적으로 중요할 때 고려.
- **Firecrawl**은 기능이 많지만 self-host가 무겁고 일부 기능이 클라우드 전용이에요.

> 참고: 서비스를 따로 안 띄우고 **확장 안에서 가볍게** 끝내고 싶으면, `fetch` + Readability(+Turndown) 조합도 있어요. 정적 페이지엔 충분하지만 JS 렌더링이 빠져서 품질 상한이 낮아요. 우리는 품질을 위해 Jina Reader로 갑니다.
