# 웹 검색은 어떻게 작동하나요

## 이게 뭐예요?
로컬 모델(내 맥북에서 도는 [[pi]]의 두뇌)은 학습할 때 본 지식만 알아요. 인터넷에 직접 연결돼 있지 않습니다. 그래서 "오늘 환율" 같은 걸 물으면 모르거나 지어내요. **웹 검색을 붙인다는 건, 모델한테 인터넷을 대신 뒤져서 자료를 가져다주는 심부름꾼을 붙여주는 일**이에요.

그런데 이 심부름이 한 가지 일이 아니라 **두 가지 일**로 나뉩니다. 이걸 먼저 이해해야 뒤에 나오는 도구들([[웹검색엔진-유료옵션]], [[웹검색엔진-무료옵션]])을 고를 때 안 헷갈려요. 지금은 가볍게 그림만 잡고 가도 충분합니다.

## 비유: 도서관 사서
검색을 도서관에서 자료 찾는 일로 생각하면 쉬워요.

1. 사서한테 "이 주제 책 좀요" 하면, 사서가 **관련 책 목록**을 줍니다. 아직 책 내용은 안 읽었어요. 제목이랑 짧은 소개만 봐요.
2. 그 목록에서 **실제 책을 펴서 필요한 부분을 읽어요.** 이때 비로소 내용을 알게 됩니다.

웹 검색도 똑같이 두 단계예요.

## 1단계: 검색 (목록 받아오기)
질문을 검색엔진에 넣으면, 관련 있는 **웹페이지 링크 목록**을 돌려줘요. 각 항목엔 제목, 주소(URL), 그리고 한두 줄짜리 요약(스니펫, snippet)이 붙어 있습니다.

여기서 중요한 점. **아직 페이지 내용 전체를 받은 게 아니에요.** 목록과 짧은 미리보기뿐입니다. 사서가 준 책 목록이랑 같아요.

이 일을 해주는 게 검색엔진 API(Tavily, Brave, SearXNG 같은 것)예요.

## 2단계: 읽기 (들어가서 정보 추출)
목록에서 쓸 만해 보이는 링크를 골라, **실제로 그 페이지에 들어가서 본문을 긁어옵니다.** 웹페이지엔 광고, 메뉴, 댓글 같은 잡동사니가 잔뜩 섞여 있어요. 거기서 **진짜 본문만 깨끗한 텍스트로 뽑아내는 것**이 이 단계의 핵심입니다.

이렇게 추출한 본문을 모델한테 넘겨주면, 그제서야 모델이 제대로 된 답을 만들 수 있어요.

## 왜 굳이 둘로 나누나요?
1단계 요약(스니펫)만 보고 답하면 부정확해요. 너무 짧고, 옛날 정보일 수도 있거든요. 정확한 답을 하려면 모델이 **실제 본문**을 봐야 합니다. 그래서 검색(목록)과 읽기(본문 추출)를 둘 다 하는 거예요.

도구를 고를 때 핵심이 바로 이겁니다. **어떤 도구는 1단계만 해주고, 어떤 도구는 1단계와 2단계를 다 해줘요.** 그래서 옵션 페이지의 표에 "검색만 / 검색+읽기"를 표시해 둔 거예요.

## 전체 그림 (한 번의 검색 흐름)
```
사용자 질문
   ↓
Pi가 "검색 도구" 호출          ← 1단계
   ↓
검색엔진이 링크 목록 반환 (제목 + URL + 스니펫)
   ↓
Pi가 상위 몇 개 링크를 "읽기 도구"로 열어 본문 추출   ← 2단계
   ↓
추출한 본문을 모델 컨텍스트(작업 메모리)에 넣음
   ↓
모델이 그 본문을 근거로 답 생성
```

필요하면 모델이 "자료가 좀 부족하네" 하고 검색을 다시 돌릴 수도 있어요. 이렇게 도구를 호출하고 결과를 받아 다시 굴리는 일을 [[pi]] 같은 harness가 대신 해줍니다.

## 그래서 도구는 이렇게 나눠 봐요
- **검색만 해주는 도구**: 목록만 줍니다. 본문 읽기는 따로 붙여야 해요. (예: Brave, Serper, SearXNG)
- **검색과 읽기를 다 해주는 도구**: 한 번에 본문까지 줍니다. 편하지만 보통 유료예요. (예: Tavily, Exa)
- **읽기 전용 도구**: 검색은 안 하고, 주어진 URL의 본문만 깨끗하게 긁어줍니다. 검색 도구와 짝지어 써요. (다음 primitive에서 다룰 예정)

구체적인 서비스 비교는 [[웹검색엔진-유료옵션]]과 [[웹검색엔진-무료옵션]]에서 이어집니다.

## 알아두면 좋은 용어
| 용어 | 쉽게 말하면 |
|---|---|
| 검색엔진 API | 질문을 주면 링크 목록을 돌려주는 서비스 |
| 스니펫(snippet) | 검색 결과에 붙는 한두 줄 요약 미리보기 |
| 스크래핑(scraping) | 웹페이지에서 내용을 긁어오는 것 |
| 파싱(parsing) | 긁어온 HTML에서 본문만 골라내는 것 |
| rate limit | "잠깐, 너무 자주 부르네" 하고 막는 횟수 제한 |
| 컨텍스트(context) | 모델이 한 번에 볼 수 있는 작업 메모리 |
