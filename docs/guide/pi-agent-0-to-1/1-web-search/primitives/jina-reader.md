# Jina Reader

![[Xnip2026-06-02_21-03-59.png]]
## 이게 뭐예요?
**URL 하나만 던지면, 그 페이지를 대신 읽고 광고·메뉴를 싹 걷어낸 본문만 깨끗한 마크다운으로 돌려주는 도구예요.** 내가 일일이 페이지를 열어 읽을 필요 없이, Jina Reader한테 주소만 넘기면 모델이 바로 사용하기 좋은 글로 변환해서 줍니다.

[[웹검색-원리]]의 **2단계(읽기)**를 맡는 도구이고, [[웹리더-옵션]] 중에서 우리가 고른 주인공이에요. [[searxng]]가 검색(1단계)이라면, Jina Reader는 읽기(2단계)예요.

- 코드/문서: https://github.com/jina-ai/reader
- 호스티드: https://r.jina.ai
- 라이선스: Apache-2.0 (오픈소스)
- 만든 곳: Jina AI

## 강점
- **완전 무료 오픈소스(Apache-2.0)**: Docker 이미지가 이미 빌드돼 있어서 self-host가 `docker run` 한 줄이에요. [[searxng]]랑 똑같은 패턴.
- **JS 렌더링 내장**: Puppeteer + 헤드리스 Chrome으로 JS가 그리는 페이지도 읽어내요. 게다가 **dual-engine**이라 가벼운 방식으로 먼저 시도하고, 안 되면 브라우저로 폴백해요. 품질과 속도를 같이 잡습니다.
- **마크다운으로 바로 출력**: 모델이 사용하기 좋은 형태예요. html, text, 스크린샷, json도 됩니다.
- **self-host는 제약이 없어요**: rate limit 없고, 상태도 안 들고(stateless) 매 요청이 깔끔해요.
- **검색과 대칭**: SearXNG(검색)와 Jina Reader(읽기)가 둘 다 로컬 Docker 서비스라 구조가 깔끔하게 짝이 맞아요.

## 약점
- **이미지가 무거워요**: 브라우저(Chromium)를 품고 있어서 디스크와 메모리를 SearXNG보다 많이 써요. 셋업 난이도가 아니라 덩치 얘기예요.
- **호스티드(r.jina.ai)는 제한이 있어요**: rate limit이 있고 높은 한도는 API 키가 필요해요. (우리는 self-host라 무관.)
- **순수 추출 정밀도는 1등은 아니에요**: 본문만 뽑는 정밀도 자체는 [[웹리더-옵션]]의 Trafilatura 같은 전용 추출기가 더 높아요. 다만 LLM에 제공하는 용도에선 그 차이가 작습니다.

## 우리가 Jina Reader를 고른 이유
웹 리더를 쭉 비교([[웹리더-옵션]])했을 때, **"JS 렌더링 + 본문 추출 + 마크다운"을 한 컨테이너로 다 해주면서 로컬에서 공짜로 도는 게 사실상 Jina Reader**였어요.

- **Trafilatura**는 추출 정밀도가 최강이지만 Python이고 JS를 못 읽어서, 우리 스택에선 렌더링을 따로 붙여야 해 손이 더 갑니다.
- **Firecrawl**은 기능이 많지만 self-host가 무겁고, 일부 기능이 클라우드 전용이에요.

Jina Reader는 이 둘의 번거로움 없이, **SearXNG와 똑같은 방식(Docker 서비스 + 얇은 Pi 도구)**으로 붙어요. LLM에 제공하는 용도에선 추출 정밀도 차이가 작은 대신, **JS 페이지까지 읽어내는 렌더링**이 현실에서 더 값을 합니다. 그래서 우리는 Jina Reader로 갑니다. 설치와 연동은 다음 섹션에서.
